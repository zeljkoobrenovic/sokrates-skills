# Sokrates landscape configuration — reference

Read from the Sokrates source (`codeanalyzer/.../sourcecode/landscape/`, `reports/.../landscape/`); where `docs/configuration.md` disagrees with the code, the code is cited. Parsing is tolerant: unknown keys are silently dropped and omitted keys keep their Java defaults. All files are **rewritten (normalised, pretty-printed) on every run** — comments and key order do not survive.

## Files in `_sokrates_landscape/`

| file | model | role |
|---|---|---|
| `config.json` | `LandscapeConfiguration` | the landscape settings (hand-edited) |
| `config-tags.json` | JSON **array** of `TagGroup` | repository tags (auto-created with defaults) |
| `config-teams.json` | `{ "teams": [TeamConfig] }` | contributor → team mapping (auto-created empty) |
| `config-people.json` | `{ "people": [PersonConfig] }` | identity merging, display names, avatars (generated by `updateLandscapePeopleConfigByUserName`, hand-editable) |
| `info.json` | `LandscapeInfo` | **auto-generated** index of discovered `subLandscapes` and `repositories` — never edit |
| `landscapes/`, `contributors/` | — | generated (virtual landscapes, per-person pages); **wiped on every run** |

## Discovery and the folder structure

```
analysis-root/                          # updateLandscape -analysisRoot (default ".")
├── _sokrates_landscape/config.json     # + config-tags/teams/people.json, info.json, index.html …
├── repo-a/data/data.zip                # a repository analysis (or data/analysisResults.json)
├── repo-a/html/…                       # its HTML report (htmlReportsRoot = sibling of data/)
├── team-x/_sokrates_landscape/…        # a nested folder sub-landscape
└── team-x/repo-b/data/data.zip
```

`updateLandscape` walks the analysis root once: every `*/data/data.zip` (or `data/analysisResults.json` without a sibling zip) is a repository; every `*/_sokrates_landscape/index.html` is a sub-landscape named after its grandparent folder; anything under a generated `_sokrates_landscape/landscapes/` is skipped. The discovered lists go to `info.json`; an existing `config.json` keeps all human-authored settings (only the lists and `-set*` metadata are updated). `-recursive` finds all nested `_sokrates_landscape/config.json`, deepest first. A repository's identity is its `analysisResults.metadata.name` (from the repo's `_sokrates/config.json`); with `includeOnlyOneRepositoryWithSameName: true` (default) duplicates by name are skipped, first found wins. Per repository the landscape reads `analysisResults.json`, `config.json`, the `text/aspect_*.txt` file lists (for path tags) and `text/*FilesWithHistory.txt`.

CLI: `sokrates updateLandscape [-analysisRoot .] [-confFile <path>] [-recursive] [-setName] [-setDescription] [-setLogoLink] [-addLink label href] [-date] [-timeout]`; `sokrates updateLandscapePeopleConfigByUserName [-analysisRoot] [-confFile]`. There is no separate init command: the first `updateLandscape` creates everything.

## `config.json` — `LandscapeConfiguration`

| key | default | meaning |
|---|---|---|
| `metadata` | `{}` | `name`, `description`, `tooltip`, `logoLink`, `links[{label,href}]`. Blank name at init → `"<Folder> Landscape"`. |
| `analysisRoot` | `"."` | folder holding the repository analyses; a value starting with `.` resolves against the folder *containing* `_sokrates_landscape/` |
| `repositoryReportsUrlPrefix` | `"../"` | prefix for links from the landscape to repository HTML reports (alias `projectReportsUrlPrefix`) |
| `parentUrl` | `""` | title link target |
| `breadcrumbs` | `[]` | `[{label, href}]` |
| `extensionThresholdLoc` | `0` | extensions below this main LOC are hidden |
| `repositoryThresholdLocMain` | `0` | repositories below this main LOC are excluded (alias `projectThresholdLocMain`) |
| `repositoryThresholdContributors` | `1` | repositories with fewer contributors excluded — **repos with zero contributors are never excluded by this** |
| `contributorThresholdCommits` | `1` | contributors (and bots) below this many commits are dropped |
| `ignoreRepositoriesLastUpdatedBefore` | `""` | `YYYY-MM-dd`; drop repositories whose latest commit is older |
| `includeOnlyOneRepositoryWithSameName` | `true` | |
| `commitsMaxYears` | `10` | years of history shown in charts |
| `significantContributorMinCommitDaysPerYear` | `10` | |
| `repositoriesShortListLimit` | `100` | **dead** — read nowhere |
| `repositoriesListLimit` | `1000` | cap for features-of-interest aggregation |
| `repositoriesHistoryLimit` | `30` | years of per-repository history exported |
| `contributorsListLimit` | `1000` | how many contributors get individual pages |
| `maxSublandscapeDepth` | `0` | 0 = all; virtual sub-landscapes count as depth 1 |
| `anonymizeContributors` | `false` | `Email N` / `User N` |
| `contributorLinkTemplate` / `contributorAvatarLinkTemplate` | `""` | `${contributorid}` = email with `@…` stripped, e.g. `https://avatars.githubusercontent.com/${contributorid}` |
| `ignoreContributors` | `[]` | regexes (lower-cased, full-string) — dropped entirely; applied before **and** after email transforms |
| `bots` | `[".*\\[bot\\].*", ".*[-]bot[@].*"]` | regexes (case-insensitive, full-string); bots get their own tab, are excluded from contributors and teams |
| `transformContributorEmails` | `[]` | `[{"op": "replace|remove|extract|trim|lowercase|uppercase|append|prepend", "params": [...]}]` applied in order before people matching, e.g. `{"op":"replace","params":["[@].*",""]}` strips domains, `{"op":"replace","params":["[0-9]+[+]",""]}` strips GitHub noreply ids |
| `tagContributors` | `[]` | `[{"name", "patterns": [regex]}]` — case-insensitive, full-string on email |
| `ignoreExtensions` | `[]` | exact extension strings excluded landscape-wide |
| `mergeExtensions` | `[]` | `[{"primary": "yaml", "secondary": "yml"}]` folds secondary into primary |
| `showRepositoryControls` | `true` | |
| `showContributorsTrendsOnFirstTab` | `true` | |
| `iFramesAtStart`, `iFrames`, `iFramesRepositoriesAtStart`, `iFramesRepositories`, `iFramesContributorsAtStart`, `iFramesContributors` | `[]` | `[{title, src, style, scrolling: true, moreInfoLink}]` embeds on the tabs |
| `customTabs` | `[]` | `[{"name": "More", "iFrames": [...]}]` |
| `customHtmlReportHeaderFragment` | `""` | raw HTML in every page header |
| `virtualLandscapes` | empty | see below |

Not fields (ignored if present): `showExtensionsOnFirstTab`, `ignoreRepositories`, `contributorAliases`, `maxRepositoriesOnList`, `people`, `teams`, `tagRules` (that is a repository-config key).

### Virtual landscapes

```json
"virtualLandscapes": {
  "remainderLandscapeMetadata": { "name": "Remainder" },
  "landscapes": [
    { "metadata": { "name": "Platform" },
      "includeRepoNamePatterns": [".*-platform-.*", "core-.*"],
      "excludeRepoNamePatterns": [".*-deprecated"],
      "virtualLandscapes": { "landscapes": [ { "metadata": {"name": "Agents"}, "includeRepoNamePatterns": [".*agent.*"] } ] } }
  ]
}
```

Membership: include list non-empty AND repository **name** matches any include AND matches no exclude — **case-sensitive**, full-string regex (unlike every contributor matcher). A repository may be in several virtual landscapes; those in none go to the Remainder. Each virtual landscape gets a full report under `_sokrates_landscape/landscapes/<name>/_sokrates_landscape/` (regenerated each run) with a derived config (`analysisRoot` and `repositoryReportsUrlPrefix` prefixed with `../` levels). Nesting is unlimited.

## `config-tags.json` — `TagGroup[]`

```json
[ { "name": "tech", "description": "", "color": "#A3C1AD",
    "repositoryTags": [
      { "tag": "kotlin", "patterns": [], "excludePatterns": [],
        "mainExtensions": ["kt"], "anyExtensions": [], "excludeExtensions": [],
        "pathPatterns": [], "excludePathPatterns": [], "imageLink": "" } ] } ]
```

Per repository, tag matching (`TagMap.isTagged`): exclusions first — `excludeExtensions` (equalsIgnoreCase on the **dominant** extension) or `excludePatterns` (regex on the repository name) veto; then OR of: `patterns` (regex on name, case-sensitive, full-string), `mainExtensions` (equalsIgnoreCase, dominant extension), `anyExtensions` (equalsIgnoreCase, any extension present), `pathPatterns` (regex on **every file path** of the repository, all scopes; one matching file tags the repo; `excludePathPatterns` evaluated per file). No matching on contributors. Defaults written on first run: groups "CI/CD tools", "build and dependencies management tools", "tech" with path-pattern tags (jenkins `(|.*/)Jenkinsfile`, github actions `(|.*/)[.]github[/]workflows[/].*`, maven `(|.*/)pom[.]xml`, docker `(|.*/)Dockerfile`, npm, gradle, bazel, helm, …); the "ui tech" group (react/vue/android) is built but **not** written — add it by hand. Extension tag groups ("main file extensions", "all file extensions") are generated automatically and are not configurable. `projectTags` is a legacy alias of `repositoryTags`.

## `config-teams.json` — `TeamsConfig`

```json
{ "teams": [ { "name": "Payments", "description": "", "emailPatterns": [".*@payments[.]example[.]com", "alice@example.com"], "userNamePatterns": ["Bob .*"] } ] }
```

A contributor belongs to the **first** team whose `emailPatterns` match the (post-transform, post-people) canonical email or whose `userNamePatterns` match the user name — case-insensitive, full-string regex, so literal emails work. Bots are skipped. Unmatched contributors go to "Undefined Team" only if active in the last 180 days. Empty `teams` = no team reports.

## `config-people.json` — `PeopleConfig`

```json
{ "people": [ { "email": "alice@example.com", "userName": "Alice Example", "links": [{"label": "GitHub", "href": "https://github.com/alice"}], "image": "",
                "emailPatterns": ["\\Qalice@example.com\\E", "\\Q12345+alice@users.noreply.github.com\\E"], "userNamePatterns": [] } ] }
```

`email` is the canonical id all matches collapse into; matching is `equalsIgnoreCase(email)` OR `emailPatterns` (case-insensitive full-string regex) OR user-name key equality (whitespace stripped, lower-cased) OR `userNamePatterns`. `updateLandscapePeopleConfigByUserName` generates this file by grouping contributors with the same user-name key and writes every email as a `\Q…\E` literal pattern; it is additive and safe to re-run and to mix with hand edits. Legacy `name`/`link` keys are read but lost on rewrite — use `userName`/`links`.

Identity pipeline per contributor: lower-case email → `ignoreContributors` → `transformContributorEmails` → people config → `ignoreContributors` again → aggregate → `contributorThresholdCommits` → `bots` split → anonymise → teams.

## Regex conventions

| setting | case | anchoring |
|---|---|---|
| `ignoreContributors`, `bots`, `tagContributors`, team and people patterns | insensitive | full-string |
| repository tag `patterns` / `pathPatterns` (+ excludes), virtual landscape name patterns | **sensitive** | full-string |

An invalid regex is treated as non-matching without any error.

## Gotchas

- `repositoriesShortListLimit` does nothing; `contributorThresholdCommits` filters contributors (its source comment says repositories); zero-contributor repositories survive `repositoryThresholdContributors`.
- Companion files are rewritten every run: keep the authoritative copies under version control and diff after a run.
- `landscapes/` and `contributors/` are deleted each run — never store anything there.
- Virtual-landscape name matching is case-sensitive; team/people matching is not.
- A repository whose `_sokrates/config.json` has a blank `metadata.name` collides with every other blank-named one (first wins).
- Sub-landscape reports must be generated before the parent (`-recursive` orders deepest-first for this reason).
